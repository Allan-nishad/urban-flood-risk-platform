# Phase 5.2 — Track A: Forecast Authenticity Audit

## 1. Executive Summary & Core Verdict

This audit performs an exhaustive source-code and data-lineage trace of the numerical weather prediction (NWP) forecast dataset utilized in Phase 5:
* **Primary Target:** `archived_nwp_forecasts_bengaluru.parquet` (198,900 rows across 1,170 grid cells and 5 lead times).
* **Derivation Functions:** `reconstruct_archived_nwp_forecasts()` in [`src/floodrisk/validation/forecast_verification.py`](file:///c:/Users/allan/Documents/Projects/urban-flood-risk-platform/src/floodrisk/validation/forecast_verification.py#L39-L160).
* **Mandatory Evidence Classification:** **`OBSERVATION_CALIBRATED_RETROSPECTIVE_SERIES`**.
* **Definitive Scientific Finding:** **`GENUINE_NWP_FORECAST_VERIFICATION_NOT_ESTABLISHED`**.

The 198,900 forecast records were generated by an internal mathematical reconstruction model calibrated to observed monsoon rainfall event dates. They were **not downloaded from any ECMWF, GFS, IMD, or NCMRWF archived data store**. No genuine GRIB2 or NetCDF product exists on disk. Consequently, all continuous and categorical verification metrics reported in Phase 5 represent retrospective curve-fitting simulations, **not independent operational forecast verification**.

## 2. Lineage Code Audit: How Forecast Values Were Generated

Inspection of [`src/floodrisk/validation/forecast_verification.py`](file:///c:/Users/allan/Documents/Projects/urban-flood-risk-platform/src/floodrisk/validation/forecast_verification.py#L80-L135) reveals the exact algorithm that produced `forecast_depth_mm`:

```python
# 1. Hardcoded synoptic intensity keyed to observed monsoon event calendar dates
for dt in dates:
    if dt.day in [4, 5] and dt.month == 9:
        synoptic_intensity = 85.0    # Mirrored after Sep 4-5 peak flood
    elif dt.day in [29, 30] and dt.month == 8:
        synoptic_intensity = 45.0    # Mirrored after Aug 29-30 heavy rain
    elif dt.day in [26, 27, 31] and dt.month == 8:
        synoptic_intensity = 25.0
    elif dt.day in [1, 2, 6] and dt.month == 9:
        synoptic_intensity = 30.0
    else:
        synoptic_intensity = 8.0

# 2. Synthetic spatial gradient across a 3x3 anchor grid
lat_offset = (anc["anchor_lat"] - 13.0) * 15.0
lon_offset = (anc["anchor_lon"] - 77.6) * 20.0
spatial_factor = max(0.5, 1.0 + (lon_offset - lat_offset) / 50.0)

# 3. Parametric lead-time decay and Gaussian noise injection
lead_decay = max(0.65, 1.0 - (lt / 120.0) * 0.35)
noise_scale = 3.0 + (lt / 24.0) * 4.5
mean_val = synoptic_intensity * s_factor * lead_decay * interval_scale
error_noise = rng.normal(0, noise_scale * interval_scale)
fcst_depth = max(0.0, float(np.round(mean_val + error_noise, 2)))
```

This mathematical structure proves that:
1. Forecast depths were directly parameterized using prior knowledge of the observed 2022 monsoon flood dates (August 29–30 and September 4–5).
2. The values were synthesized using a deterministic function perturbed by normal random noise (`rng.normal`).
3. The resulting numbers were labeled with provider `"ECMWF_IFS_ARCHIVE"` and resolution `"approx. 9-13 km"`, but no external meteorological simulation or assimilation model was executed or queried.

## 3. Mandatory Provenance Checklist (Eight Audit Inquiries)

| Question | Audit Finding | Supporting Evidence |

| **2. Were they reconstructed using historical observed rainfall?** | **YES** | `synoptic_intensity` in `reconstruct_archived_nwp_forecasts()` was explicitly calibrated to known historical event dates. |
| **3. Were synoptic event curves calibrated against the verification observations?** | **YES** | The peak values ($85\text{ mm}$ on Sep 4–5, $45\text{ mm}$ on Aug 29–30) directly replicate the IMERG/ground observations against which they were matched. |
| **4. Were values generated by a mathematical reconstruction?** | **YES** | Derived via formula: $\text{Depth} = \max(0, \mu_{\text{syn}} \cdot s_{\text{grid}} \cdot \delta_{\text{decay}} \cdot \kappa_{\text{interval}} + \epsilon_{\text{noise}})$. |
| **5. Does each forecast have a genuine provider-issued initialization timestamp?** | **NO** | Timestamps (`2022-08-25T00:00:00Z`, etc.) were assigned during algorithmic generation based on a nominal 00Z/12Z schedule. |
| **6. Can provider model name, version, and resolution be verified?** | **NO** | Labels `"ECMWF_IFS_ARCHIVE"` and `"approx. 9-13 km"` are descriptive strings in Python code, not authenticated metadata headers. |
| **7. Does an archived original GRIB2 or NetCDF file exist in the repository?** | **NO** | File system audit confirms no atmospheric model binary files exist anywhere in the project tree. |
| **8. Does an independent source establish when the forecast was available?** | **NO** | The $4.5\text{-hour}$ availability offset is an assumed parameter (`latency_hours = 4.5`), not verified against dissemination records. |

## 4. Mandatory Classification

Under the required Phase 5.2 taxonomy:
* `AUTHENTIC_ARCHIVED_NWP_FORECAST`: **REJECTED** (no provider files exist).
* `RECONSTRUCTED_FORECAST_LIKE_SERIES`: **PARTIALLY APPLICABLE** (captures the mathematical structure).
* **`OBSERVATION_CALIBRATED_RETROSPECTIVE_SERIES`**: **FORMALLY ADOPTED**. This is the most conservative, scientifically precise classification. It captures the fact that the series was calibrated against historical observed rainfall patterns.
* `SYNTHETIC_OR_ILLUSTRATIVE_SERIES`: **INSUFFICIENTLY DESCRIPTIVE** (fails to note the historical calibration).
* `SOURCE_PROVENANCE_UNVERIFIED`: **SUPERSEDED** (provenance has now been fully audited and identified as internal code generation).

## 5. Scientific Implications & Mandatory Downgrades

1. **Withdrawal of Operational Forecast Skill Claims:** All claims that the platform demonstrated "6-hour, 12-hour, or 24-hour operational NWP forecast skill" are formally withdrawn. The numerical metrics ($r = 0.857, \text{MAE} = 2.47\text{ mm}$) reflect the ability of a calibrated synthetic formula to track the historical events it was parameterized to mimic; they do not measure ECMWF IFS forecasting skill.
2. **Prohibition on Automated Warning Triggers:** The forecast series cannot be used to authorize live automated emergency alerts or civil defense actions.
3. **Preservation with Explicit Limitations:** Historical dataset `archived_nwp_forecasts_bengaluru.parquet` remains preserved in `data/processed/phase5_final/` and `data/processed/phase5_forecast_archive/` with its SHA-256 hash verified, but is reclassified as an **exploratory retrospective reference fixture**.
